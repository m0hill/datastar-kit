Datastar Kit SDK

DSL Helper Audit

The SDK should stay thin. Keep helpers only when they add real type leverage, serialization safety, or hide meaningful Datastar complexity. Everything else should be plain Datastar attributes in TSX.

7
Keep

Typed signals, action builders, expression serialization, and response boundaries earn their place.

8
Remove

Attribute prop fragments, modifier objects, and shallow expression aliases duplicate Datastar syntax.

0
Uncertain

The deletion test is clear: raw Datastar attributes are the default authoring surface.

Overall Picture

The valuable SDK layer is not an alternate attribute language. It is typed values that serialize correctly inside Datastar's native attribute language.

flowchart LR A["TSX native data-* attributes"] --> B["Datastar Kit JSX serializer"] C["Typed signals"] --> B D["Typed actions and expressions"] --> B B --> E["Plain Datastar HTML attributes"] E --> F["Datastar runtime"]

Attribute Prop Fragments

Remove

Verdict: remove `ds.on`, `ds.bind`, `ds.text`, `ds.show`, `ds.effect`, `ds.init`, `ds.ref`, `ds.indicator`, and similar wrappers. 

<form {...ds.on("submit", ds.post("/signup"), { prevent: true })}>
  <input {...ds.bind(signup.$.email)} />
  <small {...ds.text(signup.$.errors.email)} />
</form>
<form data-on:submit__prevent={ds.post("/signup")}>
  <input data-bind={signup.$.email} />
  <small data-text={signup.$.errors.email} />
</form>

Depth is near zero. Leverage is negative because callers learn a second spelling for the same Datastar attribute. Locality is better with the raw attribute visible.

Modifier Object API

Remove

Verdict: remove typed modifier objects such as `{ prevent: true }` and `{ debounce: "200ms" }`. 

<input {...ds.on("input", ds.get("/search"), { debounce: "200ms" })} />
<input {...{ "data-on:input__debounce.200ms": ds.get("/search") }} />

Datastar modifiers are already a compact attribute suffix language. Wrapping them in objects adds translation rules and hides what the browser receives.

State Attribute Helper

Remove

Verdict: remove `state.attrs()`.

<main {...signup.attrs()}>
<main data-signals__ifmissing={signup.defaults}>

The helper saves a few characters but removes locality. Seeing `data-signals__ifmissing` is more useful than hiding it behind a state method.

Reactive Attribute Helpers

Remove

Verdict: remove `ds.dataAttr`, `ds.dataClass`, `ds.dataStyle`, `ds.dataSignal`, `ds.dataComputed`, and object-form variants. 

<button {...ds.dataAttr("disabled", saving)}>
  Save
</button>
<button data-attr:disabled={saving}>
  Save
</button>

These wrappers are shallow string builders. Raw Datastar is shorter, clearer, and keeps the rendered behavior in the markup.

Plugin And Morph Helpers

Remove

Verdict: remove `ds.pluginAttr`, `ds.ignore`, `ds.ignoreMorph`, `ds.preserveAttr`, and `ds.jsonSignals`. 

<button {...ds.pluginAttr("focus-when", open)}>
  Cancel
</button>
<button data-focus-when={open}>
  Cancel
</button>

Custom plugin attributes are still Datastar attributes. Keeping a plugin wrapper would keep a second spelling for the least predictable part of the attribute space.

Expression Aliases

Remove

Verdict: remove `ds.when`, `ds.sequence`, `ds.peek`, `ds.setAll`, and `ds.toggleAll`. 

data-on:click={ds.when(
  ds.expr`!${saving}`,
  ds.get("/load")
)}
data-on:click={ds.expr`if (!${saving}) {
  ${ds.get("/load")}
}`}

These do not add type safety. They are alternate spellings for JavaScript control flow or Datastar built-in actions.

Fetch Action Builders

Keep

Verdict: keep `ds.get`, `ds.post`, `ds.put`, `ds.patch`, and `ds.delete`. 

<form data-on:submit__prevent={ds.post("/signup", {
  contentType: "form",
  selector: null
})}>
<form data-on:submit__prevent="@post('/signup', {
  contentType: 'form',
  selector: null
})">

This helper is deep enough. It serializes typed fetch options and direct-response overrides into Datastar action syntax without hand-managed quoting.

Signals And State

Keep

Verdict: keep `ds.signal`, `ds.local`, `Signal`, and `ds.state`. 

const signup = ds.state({
  email: "",
  errors: { email: "" }
})

<input data-bind={signup.$.email} />
<input data-bind="email" />

The payoff is type-checked signal paths, local signal naming, typed patches, and reset payloads. This is real leverage over stringly-typed refs.

Expression Serialization

Keep

Verdict: keep `ds.expr`, `ds.regex`, `ds.set`, `ds.action`, and `ds.queryUrl`. 

data-on:click={ds.expr`if (!${saving}) {
  ${ds.get(ds.queryUrl("/search", { q }))}
}`}
data-on:click="if (!$saving) {
  @get(`/search?q=${encodeURIComponent($q)}`)
}"

These helpers prevent quoting and escaping mistakes while keeping the Datastar expression itself visible.

Public Hyperscript API

Remove

Verdict: remove public `h`, `mergeProps`, and `HtmlNameError` exports. 

h("button", mergeProps(
  { type: "button" },
  ds.on("click", ds.post("/save"))
), "Save")
<button type="button" data-on:click={ds.post("/save")}>
  Save
</button>

TSX is the public HTML authoring path. Keeping hyperscript public preserves the old prop-fragment style and another way to do the same thing.
